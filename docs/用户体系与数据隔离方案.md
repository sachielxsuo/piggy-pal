# 用户体系与数据隔离方案设计（自用版）

> 状态：v1.0（2026-10-18）
> 范围：多宝宝、多家长、家长模式、数据隔离
> 前提：自用、非商用，服务 1–2 个宝宝（自家 + 朋友家）

---

## 一、设计原则

1. **无登录**：自用、无陌生人访问，不做账号密码/手机验证码系统。
2. **服务端单一数据源**：所有数据存在服务端 SQLite，客户端无状态（只录音 + 播放）。
3. **最小隔离**：够用即可，不过度设计，预留演进空间。
4. **防误触优先**：安全诉求是"防 4 岁宝宝误入家长设置"，不是"防黑客"。

## 二、角色与实体

| 实体 | 说明 |
|---|---|
| 家庭 `family` | （可选）跨家庭隔离的边界，一个家庭可有多个宝宝、多个家长 |
| 宝宝 `child` | 核心数据主体，档案 + 记录都挂在 child 下 |
| 家长 `parent` | 无独立账号，用 PIN 验证身份，一台设备即一个家长入口 |
| 设备 `device` | 客户端 APP 实例，无状态，连同一后端 |

## 三、多宝宝方案

- 后端建 `child` 表，每个宝宝一条记录，`child_id` 全局唯一。
- 客户端加「选宝宝」页（首次使用 + 可随时切换），**记住上次选择**。
- 之后每次请求自动带上 `child_id`，后端按 id 读写对应档案。
- 两个宝宝的档案、陪伴记录、星星数、学习进度**完全隔离**。

## 四、多家长 / 多设备方案

- 数据在服务端，**多设备天然共享**，无需同步机制。
- 每台设备装同一个 APK，连同一后端地址，选同一个 `child_id` 即共享同一份数据。
- 任何设备上的操作（看报告、改设置）实时反映，其他设备看到最新数据。
- 家长中心通过 PIN 验证进入（见下节）。

## 五、家长模式

### 5.1 模式划分

| 模式 | 入口 | 是否需要验证 |
|---|---|---|
| 宝宝模式 | 开屏「开始」 | 无，点开即用 |
| 家长模式 | 隐藏入口（如右上角小图标 / 长按） | 需 PIN 验证 |

### 5.2 家长验证（三选一，防宝宝误入）

1. **4 位 PIN 码**（家长设置，哈希存储）
2. **算术题**（如 "3+5=？"，答对进入）
3. **长按 3 秒**（最简单，但防护弱）

建议 MVP 用 **PIN 码**，兼顾简单与有效。

### 5.3 家长中心功能

- 陪伴报告（时长 / 开口次数 / 学词数）
- 时长上限设置（10/15/20 分钟）
- 内容预览（宝宝今天接触什么）
- 宝宝档案编辑（昵称、年龄、偏好）

## 六、数据模型（SQLite DDL）

### 6.1 宝宝表

```sql
CREATE TABLE child (
  child_id     TEXT PRIMARY KEY,      -- 宝宝标识（UUID）
  family_id    TEXT,                  -- 归属家庭（MVP 可空，演进用）
  name         TEXT NOT NULL,         -- 昵称，如「安安」
  age          INTEGER,               -- 年龄
  gender       TEXT,                  -- 性别
  preferences  TEXT,                  -- 偏好 JSON，如 {"likes":["动物","唱歌"]}
  avatar       TEXT,                  -- 头像（MVP 用佩奇，可空）
  created_at   TEXT
);
```

### 6.2 陪伴记录表

```sql
CREATE TABLE companion_record (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  child_id      TEXT NOT NULL,
  date          TEXT,                 -- 日期 YYYY-MM-DD
  duration_sec  INTEGER,              -- 陪伴时长（秒）
  open_count    INTEGER,              -- 开口次数
  word_count    INTEGER,              -- 习得单词数
  stars         INTEGER,              -- 星星数
  created_at    TEXT
);
CREATE INDEX idx_record_child ON companion_record(child_id, date);
```

### 6.3 学习进度表（可并入 child，独立更清晰）

```sql
CREATE TABLE child_progress (
  child_id        TEXT PRIMARY KEY,
  learned_words   TEXT,               -- 学过的词 JSON 数组
  streak_days     INTEGER,            -- 连续陪伴天数
  last_session_at TEXT,
  updated_at      TEXT
);
```

### 6.4 角色配置（roles.yaml，非数据库）

角色是静态配置，**不放数据库**，用配置文件 `roles.yaml`，后端启动时加载（加角色只改文件、不碰数据库）：

```yaml
roles:
  - role_id: peppa
    name: 佩奇
    voice_id: "tencent-yunxiaoduo"   # TTS 音色
    persona: "你是佩奇，一只 4 岁的小猪，活泼爱笑、有耐心，永远鼓励宝宝…"
    catchphrase: "嗨，我是佩奇～"
  - role_id: george
    name: 乔治
    voice_id: "tencent-yunxiaoyang"
    persona: "你是乔治，佩奇的弟弟，最爱恐龙…"
    catchphrase: "恐龙！"
```

> **角色是后端配置，无客户端创建入口**：新增角色 = 在 roles.yaml 加一个条目 + 配 TTS 音色，重启后端（或热加载）即可；客户端只「拉取角色列表 + 选角色」。

### 6.5 对话消息表（按「宝宝 × 角色」隔离，核心新增）

```sql
CREATE TABLE chat_message (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  child_id   TEXT NOT NULL,          -- 宝宝
  role_id    TEXT NOT NULL,          -- 角色（字符串，关联 roles.yaml 的 role_id）
  speaker    TEXT NOT NULL,          -- 'ai' / 'child'
  content    TEXT,                   -- 文字内容
  created_at TEXT
);
CREATE INDEX idx_chat ON chat_message(child_id, role_id, created_at);
```

> 会话上下文（进程内存）同样以 `child_id + role_id` 作为 key 隔离——佩奇的对话流和乔治的对话流互不干扰。

### 6.6 家长验证表

```sql
CREATE TABLE parent_pin (
  family_id  TEXT PRIMARY KEY,        -- MVP 可用固定值，演进为 family_id
  pin_hash   TEXT NOT NULL            -- PIN 的哈希（如 sha256 加盐 / bcrypt）
);
```

### 6.7 家庭表（演进预留，MVP 不建）

```sql
CREATE TABLE family (
  family_id  TEXT PRIMARY KEY,
  name       TEXT,
  pin_hash   TEXT,
  created_at TEXT
);
```

## 七、配置 vs 数据库（哪些放文件、哪些放库）

> 判断标准一句话：**「谁产生、谁会变」**。
> - **配置文件（YAML / .env）**：由开发者/产品规则定义，同一份对所有宝宝通用，改动低频，改了希望全局生效、不用发版不用碰库。
> - **数据库（SQLite）**：由宝宝/家长在运行时产生，每个宝宝/家庭各不相同，随时间累积、持续变化。

| 数据 | 放哪 | 具体内容 |
|---|---|---|
| 角色定义 | 配置 `roles.yaml` | role_id、name、voice_id、persona、catchphrase |
| 系统提示词 / 人设 | 配置 | 各角色 persona、全局安全护栏规则 |
| 安全护栏词表 | 配置 | 敏感词/黑名单、拒绝话术模板 |
| TTS 音色映射 | 配置 | voice_id → 腾讯云音色 code（云小朵/智小虎…） |
| 每日流程模板 | 配置 | 问候→轻互动→星星→道别→预告 的骨架 |
| 时长档位枚举 | 配置 | 可选档位（10/15/20 分钟） |
| 星星激励规则 | 配置 | 开口给几颗、阈值等固定规则 |
| 密钥 / 环境 | 配置 `.env` | 腾讯云 SecretId/Key、DeepSeek API Key、DB 路径、端口、域名 |
| 宝宝档案 | 数据库 | 昵称/年龄/偏好/头像 |
| 对话历史 | 数据库 | chat_message（child_id+role_id 隔离） |
| 陪伴记录 | 数据库 | 时长/开口/星星汇总 |
| 学习进度 | 数据库 | 学词/连续天数 |
| 家长 PIN | 数据库 | pin_hash |
| 家长实际设置 | 数据库 | 家长选中的时长上限等「用户选择的值」 |

> **易混点**：时长「档位枚举」（10/15/20）放配置，但家长「具体选中的值」（安安设了 15 分钟）放数据库——规则固定放文件，用户的选择存库。
>
> 一句话：**「产品规则 / 角色 / 音色 / 提示词 / 密钥」放配置文件；「宝宝档案 / 对话 / 记录 / 进度 / PIN / 设置值」放数据库。**

## 八、数据隔离规则

### 8.1 共享 vs 隔离总览

| 数据 | 是否共享 | 隔离维度 |
|---|---|---|
| 宝宝档案（昵称/年龄/偏好） | 共享（多家长可看） | `child_id` |
| 陪伴记录（时长/星星汇总） | 共享（宝宝整体表现） | `child_id` |
| 学习进度 | 共享 | `child_id` |
| **对话历史（聊天）** | **独立** | **`child_id` + `role_id`** |

### 8.2 隔离依据

| 维度 | 隔离依据 | 说明 |
|---|---|---|
| 宝宝之间 | `child_id` | 档案、记录、进度全部按 child_id 隔离 |
| 角色之间 | `role_id` | 对话历史按「宝宝 × 角色」隔离，每个角色独立记忆 |
| 家庭之间 | `family_id` | 跨家庭边界（朋友家 vs 你家），MVP 可暂用 child_id + 各自 PIN 代替 |
| 家长访问 | PIN 验证 | 通过验证才能看报告/改设置 |

**隔离保证**：档案/记录 SQL 带 `child_id` 条件；对话历史 SQL 带 `child_id + role_id` 条件；家长端接口先验 PIN，再返回数据。

## 九、接口设计（REST 风格）

### 9.1 宝宝端（无验证，带 child_id）

```
GET  /child/:child_id               # 读宝宝档案（后端拼 LLM prompt 用）
POST /child/:child_id/session       # 开始一次陪伴会话（body 带 role_id 指定角色）
POST /child/:child_id/chat          # 单次对话，body 带 role_id（语音 → ASR → LLM → TTS）
```

### 9.2 家长端（需 PIN 验证）

```
POST /parent/verify                 # 校验 PIN，返回临时凭证（可选）
GET  /parent/children               # 列出宝宝（家长可切换查看）
GET  /parent/:child_id/report       # 陪伴报告
PUT  /parent/:child_id/settings     # 改时长等设置
PUT  /parent/pin                    # 修改 PIN
```

> 自用场景 PIN 验证可极简：`/parent/verify` 传 PIN，后端比对哈希，通过即放行（可用简单 token 或 session 标记）。

## 十、安全与边界

1. **PIN 哈希存储**：不存明文，用加盐哈希（如 `sha256(salt + pin)`，或用 bcrypt）。
2. **跨家庭隔离**：MVP 阶段靠"child_id + 各自 PIN 互不告知"即可；若担心，演进时引入 `family` 表 + PIN 绑定 family。
3. **无需 HTTPS 之外的额外防护**：自用无陌生人，PIN 防的是"宝宝误触"而非"攻击"。
4. **录音/隐私**：宝宝语音不落盘（或本地临时处理即删），档案仅昵称/年龄/偏好，无敏感信息。

## 十一、演进路径

| 阶段 | 方案 |
|---|---|
| **现在（MVP）** | 无登录，`child_id` 区分宝宝，PIN 验证家长，无 family 表 |
| **朋友家也接入** | 沿用 child_id + 各自 PIN（简单隔离），或引入 `family` 表做规范隔离 |
| **公开 / 商用** | 引入手机号/微信登录、family 归属、数据合规，届时再上完整账号体系 |

## 附：关键结论一句话

**数据放服务端、客户端无状态 → 多宝宝靠 child_id、多家长靠共享服务端数据、家长模式靠 PIN、隔离靠 child_id + family_id，全程无需登录。**
