# 技术选型与方案设计（自用版）

> 状态：v1.1（2026-10-19，更新部署方案：Docker → 裸二进制 + systemd + Caddy 自动 HTTPS）
> 范围：客户端 / 后端选型、目录与架构、部署方案、代码仓库规划
> 前提：自用、非商用，服务 1–2 个宝宝；Android 首发；服务器 = 腾讯云香港轻量服务器（203.0.113.10，免备案）；域名已备案

## 一、选型总览

| 层 | 选型 | 理由（自用版） |
|---|---|---|
| 客户端 | **Flutter**（Android 首发，预留 iOS） | 一套代码跨端；动画/口型/音频生态成熟；后续装 iPhone 只需再交 99 美元开发者账号，代码不用重写 |
| 后端语言 | **Go** | 用户有学习意愿；单二进制部署；goroutine 并发强、腾讯云 SDK 齐全（ASR/TTS）；性能/部署/可维护的好平衡 |
| 后端框架 | **Gin** | 最主流、社区最大、文档教程多，适合边学边做 |
| 数据库 | **SQLite**（modernc.org/sqlite） | 纯 Go 实现、无 cgo，交叉编译单二进制简单；单文件零运维 |
| 对话通道 | **HTTP + SSE 分阶段**（POST /child/:id/chat/stream） | 宝宝说完立刻看到自己说的文字，佩奇回复文字先出、语音按句跟上；比 WebSocket 简单，仍走普通 HTTPS |
| 大模型 | **DeepSeek 官方 API** | OpenAI 兼容、中英都稳、按量便宜；腾讯云 Token Plan 官方禁止用于自建后端，已排除 |
| ASR / TTS | 腾讯云（跑通优先） | 统一厂商、直连低延迟；ASR 后续可换讯飞（插件式） |
| 部署 | **裸二进制 + systemd**（首选）/ Docker 备选 | 单二进制交叉编译 scp 即跑，省内存免镜像构建；systemd 守护自启；Caddy 反代自动 HTTPS |
| 代码托管 | **Gitee / GitHub 私有仓库** | 不用工蜂；国内拉取快选 Gitee，要 CI/生态选 GitHub；均免费私有 |

## 二、客户端选型

### 2.1 框架：Flutter

- **为什么不是 React Native / 原生**：
  | 选项 | 结论 |
  |---|---|
  | Flutter | ✅ 选中。UI 一致、动画强、一套代码 Android+iOS |
  | React Native | 用户熟 React 可上手，但音频/口型生态与原生桥接成本略高 |
  | 原生 Android（Kotlin） | 性能最好，但只覆盖单端、开发量翻倍 |
- **依赖选型**（音频与状态）：
  - 录音：`record`（AAC/m4a）
  - 播放：`just_audio`（播放 TTS 返回的音频）
  - 网络：`dio`（HTTP 客户端）
  - 权限：`permission_handler`（麦克风）
  - 本地缓存：`shared_preferences`（记 child_id）
  - 开发者模式：关于页顶部双击 / 长按切换本地开关 `dev_mode`，选宝宝页据此显示 / 隐藏测试宝宝（`family_id=dev` 或 `child_id` 以 `dev_` 开头）
  - 状态管理：`setState`（自用轻量，不引入 riverpod）
- **角色形象**：佩奇 PNG + 简单帧动画（呼吸/说话口型 2–3 帧），不引入 Live2D。

## 三、后端选型

### 3.1 语言：Go

| 对比 | Go | Node.js + TS | Python (FastAPI) | Rust |
|---|---|---|---|---|
| 腾讯云 SDK 齐全度 | ✅ asr/tts 全 | ✅ 全 | ✅ 全 | ❌ 仅 ASR（TTS 无官方） |
| 部署 | ✅ **单二进制**，免装运行时 | 带运行时（Docker 可抹平） | 带运行时 | 单二进制 |
| 实时语音（WS） | ✅ gorilla/websocket | ✅ ws | FastAPI 可用 | tokio 强、心智高 |
| 本机性能 | 高 | 中 | 中 | 最高（但用不上） |
| 迭代速度 | 中（静态类型，边学边做略慢） | 快 | 快 | 慢 |
| 结论 | ✅ **选定**（用户有意愿学习） | 候选 | 候选 | 不选 |

### 3.4 对话链路（SSE 分阶段）

```
宝宝按住说话 → 客户端录音 → 松开 → POST /child/:id/chat/stream（audio_b64）
  → ASR 完成：立刻推 event: asr   {child_text}      → 宝宝气泡先上屏（文本链路 ~0.2s；真实语音再加 ASR 约 0.4–0.6s）
  → 拼 system prompt（角色人设 + 安全护栏 + 宝宝身份/年龄/喜好 + 从 SQLite 取该 child_id+role_id 历史记忆）
  → LLM 完成：推 event: reply     {reply_text, stars} → 佩奇气泡先出文字（实测 ~1.1s）
  → TTS 按句合成：每句完成推 event: audio             → 客户端排队播放（文本链路首句 ~2.3s，真实语音约 2.5–3s 出声）
  → 同时写 chat_message（child_id+role_id）落库、结算星星
```

- 旧 `POST /child/:id/chat` 保留不动，已安装的旧版本继续可用；新客户端走 `/chat/stream`。
- SSE 事件顺序固定 `asr → reply → audio`（audio 可能多段）。角色不存在 / 空输入在开始流之前就用 404 / 400 返回，不先写 200。
- 服务端每写一个事件就 `Flush()`；Caddy 对 `/child/*/chat/stream` 关闭压缩并设 `flush_interval -1`，否则事件会攒在缓冲区里，失去分阶段的意义。
- 某一句 TTS 失败只跳过该句，回复文字和后续句子不受影响；客户端断开后服务端立即停止，不再继续烧 LLM/TTS。

- 无密钥时优雅降级：LLM 走 mock 回复、无 TTS 音频，保证本地可跑。
- 历史记忆按 `child_id + role_id` 隔离（每个角色独立记忆）。
- 宝宝档案里的中文名 / 英文名 / 年龄 / 喜好会拼进 system prompt：名字用于自然称呼，年龄用于控制句长和词汇难度，喜好用于自然带入话题（截断 60 字，避免挤占 prompt）。
- **音色与声音复刻**：`roles.yaml` 支持两种写法——`voice_id` 填数字音色 ID（精品 / 大模型 / 基础版复刻返回的 VoiceType 都走这里）；`fast_voice_id` 填一句话版声音复刻返回的 `FastVoiceType`（如 `WCHN-xxx`），填了它服务端会自动用腾讯云约定值 `VoiceType=200000000` 并忽略 `voice_id`。一句话版只需 5–15 秒录音，比基础版（10–20 分钟、单价高）适合自用；克隆请用有授权的录音。
- TTS 结果按「音色 + 语速 + 文本」hash 落盘缓存，重复话术直接命中，省 TTS 成本。
- 缓存落在 `DATA_DIR/tts-cache`，部署/重启都不会清空；只有改文案或换音色（hash 变化）才会重新合成一次。
- 角色首页语音在服务启动时预热：缓存命中时只是读文件（0 成本），不会因为发版重新生成。
- 每日时长上限存在本地 `SharedPreferences['daily_limit_min']`：`5~60` 分钟为限时，`0` 表示「不限时」（周末家长陪同）。不限时时对话页顶部显示「不限时」，不跑倒计时也不自动道别；点「结束」仍会正常上报时长、结算今日星星。修改后下一次进入陪伴页生效。
- **客户端唯一标识**：不能用 `child_id`（同一宝宝可多台设备）或全站共享的 `API_TOKEN`（所有设备相同）。用 Android 的 `ANDROID_ID`（SSAID）派生 `client_id = a_<16 位 hex>`——同一签名 + 同一用户下**卸载重装不变**，恢复出厂 / 换签名才变；取不到（iOS / 模拟器 / 通道异常）时降级为首次启动随机生成的 `c_<32 位 hex>`（这种情况重装会变）。**不用 IMEI**：Android 10 起普通应用拿不到（需要 `READ_PRIVILEGED_PHONE_STATE`），Play 政策也禁止。心跳、日志上传都带 `client_id`，服务端 `client_device` / `session_run` / `client_command` 按它隔离，日志落 `client_logs/<client_id>/`（「关于」页手动上传和服务端指令提取走同一个接口，同一设备的日志同目录；无 `client_id` 的旧版本归到 `_legacy/`）；设备可读名用品牌 + 型号（`vivo V2025A · Android 15`）。
- **心跳（30s）**：App 前台每 30 秒 `POST /client/heartbeat`，退后台停表、回前台立刻补一次。心跳同时承担四件事：上报本次陪伴累计时长、领取服务端指令、接收新版本通知、刷新设备信息。
- **语音与反馈节奏**：TTS 语速按角色配置（`roles.yaml` 的 `speed`，佩奇 0.9 / 乔治 0.85），缓存键含语速；得星播放本地短音效（`assets/sfx/`），达成 10 颗换更长的庆祝音；倒计时剩 2 分钟 / 30 秒由服务端下发固定文案的语音预告（`GET /roles/:id/time-warning`），录音中自动延后播放，避免「突然结束」。
- **本地日志**：`logs/app-YYYY-MM-DD.log`，跨零点自动切分，只保留最近 14 天；「关于」页手动上传与服务端指令提取都取这份日志。
- **数据库备份**：systemd timer 每天 03:30 用 `sqlite3 .backup` 做在线热备，gzip 后放 `data/backups/`，保留 14 天，备份完自动 `integrity_check`；暂不同步 NAS。
- **新版本通知**：心跳响应按 `version_code` 比对 `latest.json`，有新版本时带 `app_update`。客户端据此①亮红点（首页左上角三横线 + 抽屉「关于」+ 家长中心「关于」同步）②弹一次原生 Toast（`piggy_pal/ui` 通道，非 Android 降级 SnackBar，同一版本只提示一次）。红点是「未看过」状态（本地记 `seen_update_code`），家长进过一次「关于」内外红点一起消掉，但「关于」里的新版本文案保留。仍不自动更新、不弹对话框，只提示家长去「关于 → 检查更新」。
- **时长上报幂等**：客户端上报的是「本次运行（`run_id`）的累计秒数」，服务端 `session_run` 记录已计入值，只把 `max(新, 旧) - 旧` 的差额补进当天统计——网络重试、乱序到达都不会多算；进程被杀最多丢最后一个 30 秒（原来是整场丢）。
- **服务端指令**：`client_command` 表按 `client_id` 存待执行指令，心跳响应携带；已下发但 10 分钟没回执的会自动重发；客户端执行后 `ack` 回执。目前一条：`upload_logs`（提取最近 24 小时客户端日志）。
- **管理接口**：`/admin/*` 额外要求 `X-Admin-Token`（env `ADMIN_TOKEN`），未配置时整体 404；该令牌不编译进客户端。
- 客户端自动更新采用**全量 APK**：APK 与 `latest.json` 放在服务器 `data/releases/`，启动 2 秒后静默检查 `GET /app/latest`，versionCode 大于本地时把结果写进 `AppUpdater.availableUpdate`，**只更新红点状态、不自动弹窗**（避免打断正在进行的亲子陪伴）；家长自己点「关于 → 检查更新」才走更新流程，确认后下载到 cache（带进度、校验大小与 sha256），再通过 FileProvider 拉起系统安装器。Android 不允许静默安装，最后一步由用户确认；缺少「安装未知应用」权限时自动跳设置页，授权返回后自动续装。不做差量更新：bsdiff 补丁需要为每个历史版本维护基线、端上做二进制合并并处理签名 / ABI 差异，失败即装不上，20MB 全量更稳。界面上的版本号默认只显示 versionName（`v1.0.2`），只有开发者模式下才带上 versionCode（`v1.0.2 (3)`）——构建号是发版比对用的，家长不用看。
- **APK 签名固定**：沿用 2024-01-17 生成的 debug keystore（`CN=Android Debug`，SHA-256 `a8:ec:22:…:b5:6e`，有效期至 2054-01-09），keystore 放项目外 `~/keys/piggy-pal-debug.keystore`，由 `client/android/key.properties`（不进 git）显式引用。理由：已装设备只认同一签名，换 key 会导致 `INSTALL_FAILED_UPDATE_INCOMPATIBLE` 必须卸载重装，且 `ANDROID_ID` 按签名派生、`client_id` 会变。`build.gradle.kts` 缺失配置时 release 构建直接失败（debug 不受影响），`release_apk.sh` 打包后用 `apksigner` 校验 SHA-256，不一致拒绝发布。换机恢复步骤见 `docs/故障排查.md` 2.2。
- 结束页展示「今日累计」：退出时先 `POST /child/:id/session` 上报本次时长，再查 `GET /child/:id/stats`，用当天的累计星星 / 时长渲染结束页和道别语音。这样当天玩满时长后再次进入、立刻被温柔收尾时，也不会显示 0 分钟 / 0 颗星。网络异常 3 秒超时则回退到本次会话数据。
- 会话与对话记录：同一个宝宝 + 同一个角色固定一个会话（`sess_<child_id>_<role_id>`），不再每次进入新建；对话历史在同一个线程里完整展示，剩余时长 / 星星 / 每日上限仍按自然天统计。对话记录按 `child_id + role_id` 落库 `chat_message`（宝宝说的 + AI 回复 + 每天的开场话题）。进入对话页先读本地最近 30 条秒开（断网可用），再用服务端最近一页覆盖刷新；上滑到顶部时用 `before_id` 向服务端拉更早的一页，插入后按 `maxScrollExtent` 差值修正滚动位置。历史为空才用角色默认开场白；当天首次生成的欢迎语会直接写入 chat_message，所以拉历史时它就是最新一条（客户端不再单独插气泡）；只有当天首次生成且本次会话还没开口时才自动播放。本地缓存只存消息 ID、说话人和文本（`SharedPreferences`，键含宝宝 + 角色），不存音频。
- 更激进的 WebSocket + 流式 ASR / 流式 LLM 仍留作后续优化；当前的「按住说话整句识别 + SSE 分阶段返回」已把首个文字反馈压到 0.4–0.6s、首句出声压到 2.5–3s，对 3–6 岁宝宝够用。
- 每日开场话题：每个「宝宝 + 角色」每天首次进入对话页时，结合宝宝年龄 / 喜好 / 角色人设，同时生成中文版 + 英文版（两行，英文为完整短句），落库 `daily_greeting` 并合成角色音色 TTS；当天再次进入直接复用、不再调模型。生成时会把最近 5 天的话题作为「不要重复」提示，保证每天换一个方向。首次生成会作为一条 AI 消息写入对话历史，后续对话能自然衔接话题。

### 3.5 每周学习计划（每天 5 个新词）

目标：把「每天随机聊」变成有节奏的词汇输入，同时不改掉玩伴感。

- **节奏**：一周 7 天、每天 5 个新词，共 35 个词位（周日复习，不引入新词）。
- **为什么是 5 个**：学龄前儿童平均每天自然习得约 2.4 个词根；课堂式深教建议每周聚焦 3–5 个词（WWC 2022）；4 岁孩子要把新词记住，通常需要 10 次以上不同语境接触，Neuman 的实验里 80% 的孩子要 24 次。10 个/天摊到 10–15 分钟对话里，每个词只能出现一次，只能算“听过”；5 个/天才能让每个词反复出现 3–4 次。
  - 周一 / 周二：主题 A，优先宝宝档案里的兴趣（如恐龙、汽车），两天各 5 个，从易到难。
  - 周三 / 周四：主题 B，水果 → 日常食物这类高频生活词，两天各 5 个。
  - 周五：主题 C1，可边说边做的动作词（jump / clap / run），5 个。
  - 周六：主题 C2，颜色、身体部位、情绪里只选一类，避免一天里跳来跳去，5 个。
  - 周日：复习日，从 A/B/C 各挑 2/2/1 个本周词复现。
- **生成时机**：按 `child_id + week_start`（周一）幂等。第一次请求（首页预取 / 报告页 / 对话）时生成并落库，之后整周只读库；不在每轮对话里调 LLM。
- **生成方式**：LLM 输出 7 天 JSON → 服务端校验（7 天 × 5 词、单词为 2–9 位小写单数、当天不重复、同一个词全周最多 2 次、周日词必须来自本周）→ 不合法带原因重试 1 次 → 仍失败走内置兜底词库（动物 / 食物 / 动作颜色各 20 词，按周轮换）。
- **对话引导**：`generateReply` 把「今日主线 + 目标词状态」注入 system prompt。目标是让目标词自然出现，不是每轮都必须教学：
  - 今日主线：当天的主题（如「恐龙世界」），词藏在主题场景里；
  - 三态词表：`还没出现` / `角色说过、宝宝还没说` / `宝宝已经说过`；
  - 每次回复最多带入 1 个目标词，从「这一轮可以自然带出」里选；同一个词在宝宝说中之前最多问 2 轮，第 2 轮没接就换词或先陪玩，**不做第三次追问**；
  - 上一轮 AI 刚问过、宝宝没接的词，本轮进「不要再提」；连着两轮都问过的词升级为「绝对不要再提」（`recentAskedWords` 读最近两条 AI 消息）；
  - 宝宝提问、说自己的事、换话题时，先用一句话正面回应，再决定要不要带词；
  - 宝宝说出目标词时夸张表扬并重复发音，然后自然往下聊，不马上考下一个；
  - 不罗列词表、不说「今天学 5 个单词」「跟我读」这类课堂话术；每日开场话题也会带入 1 个新词（开场白同样计入「听到」）。
- **情绪优先**：`detectChildMood` 命中「不喜欢 / 不想 / 讨厌 / 生气 / 再见 / 不想玩」等表达时，本轮直接丢弃学习计划：
  - `moodUpset`：先接住情绪、给选择，本轮**不提任何目标词、不问英语问题**；
  - `moodLeave`：温和道别，不挽留、不谈条件（不说「再回答一个问题就让你走」）；
  - 情绪表达不计入跑题计数（那是「该停下」的信号，不是「该拐回主线」）；
  - 只收 2 字以上短语，并先剔除「要不要 / 想不想 / 喜不喜欢」这类 A 不 A 疑问句，避免正常提问被误判。
- **跑题拉回**：按宝宝「有内容但没说到目标词」的连续发言计数（`TurnsSincePlanWord`；yes / no / 嗯 这类简短回应不计，情绪表达不计，角色还没引入计划词时不计）。
  - 跑题 1 轮：先简短接住话题，再用「对了 / 你看」轻桥接带 1 个词，不生硬转折；
  - 连续 2 轮及以上：**先跟一会儿**，顺着宝宝的话题聊，最多带 1 个词；还没兴趣就只陪玩，不追问；
  - 宝宝说回目标词：计数清零，恢复主线节奏。
- **称呼一致性**：中文句只叫中文名、英文句才用英文名，不允许同一句混用（真实对话里出现过「小雨」和「Rain」混着叫）。
- **统计口径**：只统计当天计划内的词，同一个词一天只算一次。
  - `words_heard`：角色（AI）消息里出现过的计划词数；
  - `words_said`：宝宝（child）消息里出现过的计划词数；
  - 复数按 `cat/cats` 简单匹配；计划外的词一律不计。
  - 结束页直接复用 `/stats` 的今日计划数据，把「听到」和「说出」分成两条进度条展示；家长报告页同时展示词级状态与本周逐天进度。
- **数据表**：`learning_plan`（child_id + week_start，source=llm/fallback）、`learning_plan_day`（每天 theme + words JSON）。
- **接口**：`GET /child/:id/learning-plan` 返回本周 7 天、每天主题 / 词表 / 听到 / 说出；`GET /child/:id/stats` 的 `today` 和 `week[]` 增加 `plan_words / words_heard / words_said`。
- **边界**：中途改兴趣不会重排本周计划，下周生效；跨周不补生成历史计划，「近 7 天」只统计当时已生成过的日期。

### 3.6 点词查词典（内置词库 + 真人发音）

目标：聊天里点到英文单词，直接出音标、发音、中文释义和例句。4–6 岁孩子不识字，
所以**发音优先**：卡片打开就自动读一遍，再提供「慢读」按钮。

**数据源与许可**

| 用途 | 来源 | 许可 | 说明 |
| --- | --- | --- | --- |
| 中文释义 / 词形 | ECDICT | MIT | 14,156 个常用词；清洗掉 `[计][医]` 等成人/技术义项，逗号切段后丢坏段而不是整行丢（否则「n. 猫, 恶妇」会把「猫」也丢掉） |
| 音标 | CMU Pronouncing Dictionary | BSD-2 | ARPAbet 转标准 IPA（`/ˈdʒʌmp/`、`/ˈɹʌn/`），比 ipa-dict 的 /ə/ 记法更适合教学 |
| 音标兜底 | ipa-dict | MIT | CMUdict 没收录时补充 |
| 真人发音 | Wiktionary / Wikimedia Commons | CC BY-SA 3.0 / CC BY 3.0 / CC0 | 约 1,000 个高频儿童词（`audio_words.txt`，覆盖数字 / 颜色 / 动物 / 食物 / 动作等）中 983 个有录音，其余 19 个退回 TTS；服务端转 64k 单声道 mp3，正常 + 0.72x 慢读（保持音高），每条例句内标注作者与许可 |
| 例句 | 人工改写 | 本项目 | 3–6 个词，只用基础词，按 4–6 岁认知写 |

**为什么不用在线词典 API**：dictionaryapi.dev（Wiktionary）是 CC BY-SA 且有传染性，
`dinosaur` 首条释义还是科学分类、没有例句；有道仅包年且条款禁止缓存；百度词典版按字符
计费、释义仍偏成人。这些只适合做构建期参考，不适合当运行时依赖。

**分层查找**（命中即返回，不往下走）：

1. 人工审校的 169 个童词（`dict_kid`）：儿童释义 + 例句；录音词表与它解耦，约 1,000 词；
2. ECDICT 常用词底库（`dict_base`，14,156 词）：清洗后的 1–3 条释义；
3. 长尾词：LLM 生成儿童版释义 + 例句，写 `dict_enrichment` 表永久缓存；
4. 都没有：返回 `found=false`，客户端提示「佩奇还没学会这个词」。

**发音兜底**：录音词表以外的词退回现有腾讯云 TTS（按文本 + 音色 + 语速落盘缓存），
慢读用 `speed × 0.72` 再合成一份。录音词表 `audio_words.txt` 与人工童词表分离，
扩录音不需要写释义；新增词后重跑 `build_dict.py` 即可。

**词形与语境**

- 词形还原优先用 ECDICT 的 `exchange` 字段（`cats → cat`、`running → run`、`stopped → stop`），
  再用后缀规则兜底；童词先按原词命中，避免 `morning` 被拆成 `morn`。
- 点击时带上 `msg_id`，服务端从那条消息里取出包含该词的英文行，下一行中文作为翻译，
  作为「在这句话里」展示——比通用例句更有语境。

**接口**：`GET /child/:id/dict/:word?msg_id=&role_id=` 返回
`word / lemma / phonetic_us / senses[] / example / context / audio_b64 / audio_slow_b64 /
audio_source(human|tts) / audio_credit / level(kid|basic|enriched) / found`。

**数据表**：`dict_enrichment`（word 主键 + zh + example_en + example_zh + created_at）。

**构建**：`server/scripts/build_dict.py` 从 ECDICT / CMUdict / ipa-dict / kid_words.txt / audio_words.txt
生成 `dict_base.tsv.gz`、`dict_kid.tsv.gz` 和 `audio/*.mp3`，全部 `go:embed` 进二进制，
部署仍是单文件；查词只查内存，不依赖任何外部服务。

**客户端**：气泡文本按英文词切分（`TappableText`），点词时用 TextPainter 量出该词的屏幕矩形，再由 `showWordPopover` 在单词上方浮出卡片（上方空间不足时才落到下方，卡片高度受可用空间限制、内部滚动）；结果内存 LRU 缓存 40 条
（含音频），同一场对话里反复点同一个词零等待；「关于」页展示词典与发音来源。

### 3.7 星星 / 学习统计（服务端持久化）

| 接口 | 用途 |
| --- | --- |
| `GET /child/:id/stats` | 今日 / 近 7 天 / 累计的星星、时长、开口次数、连续天数；`today` / `week[]` 带计划词数与听到 / 说出数 |
| `GET /child/:id/learning-plan` | 本周学习计划：7 天主题 + 每天 5 个词 + 听到 / 说出进度（首次调用触发生成） |
| `POST /child/:id/session` | 结束陪伴时上报本次时长 + 打开次数（可带 `session_id`） |
| `POST /child/:id/session/sync` | 客户端防抖同步本次会话星星（绝对值快照，服务端只补差额） |
| `POST /child/:id/chat/stream` | 流式对话（SSE）：`asr → reply → audio` 分阶段推送；旧 `/chat` 保留兼容 |
| `POST /child/:id/bye` | 结束页：道别 + 星星结算 + 预告明日（按角色音色合成 TTS） |
| `GET /roles/:role_id/greet` | 首页角色语音：中文自我介绍 + 英文口号（按角色音色合成，走 TTS 磁盘缓存） |
| `GET /child/:id/daily-greeting/:role_id` | 每日开场话题：每天首次进入角色对话页时由 LLM 生成（中文 + 英文两行 + 角色音色 TTS），当天复用 |
| `GET /child/:id/messages?role_id=&limit=&before_id=` | 历史对话回显：按 `child_id + role_id` 正序返回（默认 50、最多 100）；`before_id` 取更早一页，响应带 `has_more` 供客户端上滑分页 |
| `GET /child/:id/messages/:message_id/audio` | 重播历史 AI 消息：按该条消息的角色音色合成，命中 TTS 磁盘缓存直接返回；宝宝消息 / 跨宝宝返回 400 / 404 |
| `POST /client/heartbeat` | 客户端每 30 秒心跳：刷新设备信息、上报本次运行累计时长（按 `run_id` 取 max 幂等）、返回待执行的指令 |
| `POST /client/commands/:id/ack` | 客户端执行完指令后回执（成功 / 失败都回，服务端据此停止重发） |
| `GET /admin/clients` | 运维用：设备列表（需 `X-Admin-Token`） |
| `POST /admin/clients/:client_id/commands` | 运维用：给指定设备下发指令，目前支持 `upload_logs` |
| `GET /admin/clients/:client_id/commands` | 运维用：查看指令状态与执行结果 |
| `GET /app/latest` | 客户端自动更新：返回 versionCode / versionName / APK 相对地址 / 大小 / sha256 / 更新说明 / 是否强制；没有发布过版本返回 404 |
| `GET /app/download/:file` | 下发 releases 目录下的 APK，支持 Range（断点续传），只允许裸文件名 + `.apk` |

- 星星规则（鼓励英文输出）：**只有宝宝说出英文单词才有星星，1 个英文单词 1 颗，单轮最多 3 颗**；只说中文 / 语气词 → 0 颗。ASR 没听清走引导话术时同样不计星星。
- 每次 `chat` 成功：按宝宝这句话里的英文单词数结算星星，`word_count` 累加实际英文词数；同时在 `companion_session` 里累加本次会话星星，响应返回 `session_stars` 作为客户端展示的权威值。
- 客户端进入对话页生成 `session_id`，星星变化后防抖约 1.2s 调 `session/sync` 上报绝对值；服务端与 `companion_session` 比对后只补差额，重复 / 延迟上报不会重复加星。结束页带 `session_id`，以服务端记录为准。
- 开口次数不单独存：直接数 `chat_message` 里该宝宝 `speaker='child'` 的条数，避免重复统计。
- 连续天数：从今天（今天还没玩则从昨天）向前数 `companion_record` 里有活动的日期，并回写 `child_progress`。
- 星星页、家长学习报告、结束页读同一份服务端数据，卸载重装/换设备都不会丢。

## 四、部署方案

### 4.1 部署形态：裸二进制 + systemd（首选）

Go 服务是「单二进制 + 纯 Go SQLite（无 cgo）」，**不需要 Docker 也能跑**。裸部署相比 Docker：省 100–200M 内存（香港轻量内存宝贵）、免镜像构建、交叉编译一个 `linux/amd64` 文件 scp 即用；Docker 仅作备选（多服务编排/环境复现时才值得）。

- **进程守护**：交给 systemd（`Restart=always` 崩溃自拉起 + `RestartSec=3` + `enable` 开机自启）。Gin 只是 Web 框架，本身不管守护/重启。
- **已落地文件**：`server/deploy/deploy.sh`（一键部署）、`server/deploy/piggy-pal.service`（systemd unit，低权限用户 piggy-pal 运行）。

### 4.2 拓扑

```
手机 App ──HTTPS──> 香港轻量服务器 (203.0.113.10)
                      ├─ Caddy 反代（自动 HTTPS，见 4.5）
                      ├─ systemd 守护的 server（Go 单二进制，/opt/piggy-pal/）
                      │     ├─ data/app.db          # SQLite
                      │     ├─ data/tts-cache/      # TTS 音频缓存
                      │     ├─ config/*.yaml        # 角色/提示词/护栏配置
                      │     └─ .env                 # 密钥（权限 600）
                      └─ 定时备份任务（见 4.7）
```

### 4.3 密钥注入（安全关键）

**原则：密钥永远运行时注入，绝不 build 进二进制/镜像。**

- 密钥只存在于服务器 `/opt/piggy-pal/.env`（权限 600），`.gitignore` 已忽略。
- 两类凭证（**不是同一个**）：

  | 用途 | 凭证 | .env 字段 |
  |---|---|---|
  | TTS + ASR（一句话识别） | 腾讯云 CAM 密钥 | TENCENTCLOUD_SECRET_ID / TENCENTCLOUD_SECRET_KEY |
  | LLM | DeepSeek API Key | LLM_TOKEN（Bearer 鉴权） |
  | 客户端门禁 | 全站共享令牌 | API_TOKEN（客户端用 X-API-Token 携带） |

  > 获取：CAM 在「访问管理 → API 密钥管理」；LLM Token 在「DeepSeek 开放平台 platform.deepseek.com → API Keys」。
  > `API_TOKEN` 是「防白嫖」门禁、不是强鉴权：打包进客户端的令牌可被反编译提取，仅适合自用；泄露后换新随机值并重新打包即可。

- 注入方式：systemd 用 `EnvironmentFile=/opt/piggy-pal/.env`；Docker 备选用 `env_file: .env`。均运行时注入。

### 4.4 环境（dev / prod）

| 项 | dev | prod |
|---|---|---|
| 后端地址 | localhost:18080 | 域名（HTTPS） |
| 数据库 | server/data/app.db（`DATA_DIR=./data`） | /opt/piggy-pal/data/app.db |
| 密钥 | 本机 .env | /opt/piggy-pal/.env（权限 600） |
| 日志 | 控制台 | journalctl -u piggy-pal -f |

> **数据库不随二进制打包**：`app.db` 只是 `DATA_DIR` 下的运行时文件。`deploy.sh` 只覆盖二进制和 `config/`，`data/` 原样保留；每次发布前还会自动备份 `app.db.bak.<时间戳>`（保留 7 天）。
> 注意两点：① 别改 `DATA_DIR` / `WorkingDirectory`，否则会指向新目录并生成空库；② 本地 dev 库不会自动上传到服务器，需要把已有宝宝档案带过去时手动 `scp server/data/app.db` 一次。

### 4.5 HTTPS 反代：Caddy + Let's Encrypt 免费证书

- **不用购买证书**。Caddy 内置 ACME，自动对接 Let's Encrypt 免费证书，签发 + 90 天自动续期全自动。
- 免费证书与商业证书在「加密强度」上无差别（都是标准 TLS），差别仅在验证级别（DV vs OV/EV）与赔付保险——自用场景用不上，选免费即可。
- 前提：域名 A 记录指向服务器 + 80/443 端口公网可达（香港轻量安全组放开 80、443）。
- 配置示意（`/etc/caddy/Caddyfile`）：

  ```
  piggy.example.com {
      reverse_proxy 127.0.0.1:18080
  }
  ```

  三行搞定：自动签 HTTPS + 反代到 Go 服务 + WebSocket 自动升级 wss（App 录音必需）。

  > 本机若已有服务占用 UDP/443（本服务器上是 hysteria），需在 Caddyfile 顶部加全局配置 `servers { protocols h1 h2 }` 关闭 HTTP/3。仓库里的 `deploy/Caddyfile` 已处理，HTTPS 仍走 TCP 的 HTTP/1.1 + HTTP/2。

### 4.6 部署步骤（一次性）

1. 服务器装 Caddy（`apt install caddy` 或官方安装脚本）。
2. 首次上传密钥：`./deploy/deploy.sh --with-env`（自动 scp `server/.env` 并 chmod 600）；也可手动 scp。
3. 一键部署：本地 `cd server && ./deploy/deploy.sh`（交叉编译 → scp 二进制+config → 建低权限用户 → systemd enable --now → 健康检查）。
4. 配 Caddy 反代域名（脚本已带 `deploy/Caddyfile`，服务器装了 Caddy 会自动覆盖+reload）+ 开放安全组 80/443。
5. 验证：`curl https://piggy.example.com/healthz`，手机走通「录音 → ASR → LLM → TTS → 播放」。

### 4.7 备份（自用从简）

- 每日凌晨 cron：`sqlite3 /data/app.db ".backup"` + `rsync` TTS 缓存目录 → 群晖 NAS。
- 保留最近 7 份，防误删。
- SQLite 单文件，备份就是复制一个文件，零成本。

### 5.2 托管与分支

- 平台：**Gitee 或 GitHub 私有仓库**（不用工蜂）。自用不公开、私有即可；国内拉取快选 Gitee，要 Actions CI/生态选 GitHub。
- 分支策略（单人简化版）：
  - `main`：可部署的稳定版（每次发版打 tag，如 `v0.1.0`）
  - `dev`：日常开发主线
  - `feature/xxx`：单个功能分支，做完合 `dev`，验证后合 `main`
- 提交规范：小批量、中文 commit 信息（沿用用户习惯），提交前跑 lint + 语法检查 + `git diff` review。

### 5.3 敏感信息不进库

- `.env`（腾讯云 SecretId/Key、DeepSeek API Key）加 `.gitignore`，只存 `.env.example` 模板。
- 宝宝真实档案/对话都在服务器 SQLite，**不提交任何真实数据**到仓库。
