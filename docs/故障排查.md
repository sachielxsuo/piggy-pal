# 故障排查（日志优先）

> 原则：**先看日志，日志定位不到再用 ADB。** ADB 只做兜底，命令必须短超时，不允许长时间挂着等。
>
> 本文里的 `203.0.113.10` / `piggy.example.com` 都是**占位符**（真实地址不入库），
> 换成本机 `deploy.env` 里的 `PIGGYPAL_SERVER` / `PIGGYPAL_DOMAIN` 后再执行。
>
> 原因：ADB 在真机上经常卡在 `adb devices` / `logcat -f`，而且 release 包的 Flutter 控制台输出很碎；App 自己的日志文件已经覆盖启动、接口、录音、失败原因，通常 1 分钟内能定位。

## 0. 一分钟流程

1. 家长端：**首页左上角菜单 → 关于 → 运行日志**
   - 点复制：最近 500 行到剪贴板
   - 点云上传：最近 2 小时上传到服务器 `/var/log/piggy-pal/client/`（文件名 = 起始时间）
2. 看日志开头：版本 / 服务地址 / token 是否注入
3. 搜 `[E]`、`[W]`、`✗`：先看第一条错误，后面多半是它的连锁反应
4. 对照服务端日志：客户端有请求、服务端没有 → 看客户端；服务端有请求但 5xx → 看服务端
5. 两边都没有线索，才用 ADB（第 4 节）

## 1. 客户端日志

### 1.1 App 内直接复制（首选）

路径：**首页抽屉 → 关于 → 运行日志 → 点一下**

- 自动复制最近 500 行到剪贴板，直接粘贴发送即可
- 副标题会显示日志目录，方便确认日志是否在写
- 日志文件位置（Android）：
  `/sdcard/Android/data/com.piggypal.piggy_pal/files/logs/app-YYYY-MM-DD.log`
- 跨过零点自动切到新文件；只保留最近 **14 天**，不会把手机存储写满
- 外部目录不可用时会回退到应用私有目录，App 内复制仍然可用，只是 ADB 拿不到

### 1.2 上传到服务器（远程排查首选）

路径：**首页左上角菜单 → 关于 → 运行日志 → 点右侧云上传图标**

- 自动截取**最近 2 小时**日志上传
- 文件名 = 这段日志的**起始时间**，例如 `2026-10-25_09-27-24.log`
- 服务端保存在 `/var/log/piggy-pal/client/`，与 `server.log` 分开目录
- 同名重复上传会自动加 `-2` / `-3` 后缀，不会覆盖之前的现场
- 上传成功会提示「已上传 xxx.log（N 行）」

服务端按 `client_id` 分目录存（一个目录 = 一台设备，互不覆盖）：

```bash
ssh root@203.0.113.10 'ls -lt /var/log/piggy-pal/client/*/ | head'
ssh root@203.0.113.10 'tail -n 200 /var/log/piggy-pal/client/<client_id>/2026-10-25_09-27-24.log'
```

- 「关于」页手动上传（最近 2 小时）和服务端指令提取（最近 24 小时，文件名带 `cmd-` 前缀）
  都落在这个目录下，同一个设备的日志放在一起
- 1.0.4 之前的旧版本不带 `client_id`，历史日志归到 `_legacy/`

### 1.2.1 服务端远程提取（不用碰手机）

App 每 30 秒一次心跳，心跳响应可以携带服务端指令。现在有一条指令：`upload_logs`。

```bash
TOKEN=$(grep -E '^API_TOKEN=' server/.env | tail -1 | cut -d= -f2-)
ADMIN=$(grep -E '^ADMIN_TOKEN=' server/.env | tail -1 | cut -d= -f2-)
H1="X-API-Token: $TOKEN"; H2="X-Admin-Token: $ADMIN"

# 1. 看有哪些设备在线（label / 版本 / 最后心跳时间）
curl -sS -H "$H1" -H "$H2" https://piggy.example.com/admin/clients | python3 -m json.tool

# 2. 让其中一台把最近 24 小时日志传上来（App 在前台时 30 秒内执行）
curl -sS -X POST -H "Content-Type: application/json" -H "$H1" -H "$H2" \
  -d '{"type":"upload_logs"}' \
  https://piggy.example.com/admin/clients/<client_id>/commands

# 3. 看执行结果（状态 pending → delivered → done，result 里有文件名和行数）
curl -sS -H "$H1" -H "$H2" \
  https://piggy.example.com/admin/clients/<client_id>/commands | python3 -m json.tool | head -20
```

- 指令下发后 `10 分钟没回执`（App 被杀 / 没网）会自动重发，不会丢
- 设备只在**前台**才心跳，App 没打开就要等下次打开
- `ADMIN_TOKEN` 没配置时 `/admin` 整体返回 404

### 1.3 电脑一行拉取（需要真机连着）

```bash
# vivo 真机：直接把最近 200 行打到终端，不做 pull、不跑 adb devices
adb -s d1193609 shell cat /sdcard/Android/data/com.piggypal.piggy_pal/files/logs/*.log | tail -200
```

> 不要先跑 `adb devices`：设备状态异常时它会卡住。设备号已知（vivo = `d1193609`），直接用。
> 真卡住了再 `adb kill-server` 后重试，超时统一加 `timeout 10`。

### 1.4 看什么

| 日志 | 含义 |
|---|---|
| `启动 release · 服务 ... · token 已注入` | 版本、服务地址、token 是否打进包 |
| `api: → GET ...` / `← 200` | 请求发出 / 返回状态码 |
| `api: ✗ ...` | 网络层失败（DNS、超时、证书、连接被拒） |
| `[E] app: 未处理的...异常` | 崩溃或未捕获异常，带堆栈 |
| `[W] child/stars/home ...` | 页面加载失败，后面跟具体异常 |
| `[W] home: 读取宝宝缓存失败` | SharedPreferences / 本地存储异常 |
| `[I] chat: 录音开始/结束` | 录音链路是否走通 |

**关键判断：日志里没有对应的 `api: →`，说明请求根本没发出去，问题在客户端（本地缓存、权限、页面逻辑），不要再去查服务端。**

## 2. 服务端日志

```bash
# 最近 200 行，看完就退出（不要 tail -f 挂着）
ssh root@203.0.113.10 'tail -n 200 /var/log/piggy-pal/server.log'
```

每行访问日志都带 `client_id`（设备）和 `child_id`（宝宝），可以直接按设备筛：

```bash
# 某台设备的全部请求
ssh root@203.0.113.10 'grep "client_id=a_480242904fa4ad48" /var/log/piggy-pal/server.log | tail -50'

# 所有 5xx（谁触发的、哪个宝宝）
ssh root@203.0.113.10 'grep "level=ERROR" /var/log/piggy-pal/server.log | tail -20'
```

关注：

- 有没有客户端对应的请求（`GET /child`、`GET /child/:id/stats`、`POST /child/:id/chat`）
- 状态码 200 / 401 / 500
- `401` → token 没注入或服务端 `API_TOKEN` 不一致
- `500` → 服务端异常，日志里会有具体错误（ASR/TTS/DeepSeek 超时等）
- 1.0.8 及更早的客户端不发 `X-Client-Id`，这些请求没有 `client_id` 字段

### 2.1 数据库备份

systemd timer 每天 **03:30** 跑一次（服务器凌晨关机 / 重启会补跑）：

```bash
# 看下次执行时间 / 最近一次结果
ssh root@203.0.113.10 'systemctl list-timers piggy-pal-backup.timer --no-pager'
ssh root@203.0.113.10 'systemctl status piggy-pal-backup.service --no-pager -l | tail -5'

# 手动跑一次（升级 / 改库结构前建议先跑）
ssh root@203.0.113.10 'systemctl start piggy-pal-backup.service'

# 备份文件（gzip，保留 14 天，权限 600）
ssh root@203.0.113.10 'ls -lh /opt/piggy-pal/data/backups/'
```

- 用 `sqlite3 .backup` 在线热备，**不需要停服**
- 备份后自动 `PRAGMA integrity_check`，坏的直接丢弃
- 恢复：解压覆盖 `data/app.db` 后 `systemctl restart piggy-pal`（先停服再覆盖）
- 目前只备 SQLite；TTS 缓存可重新生成，不备份；**尚未同步到 NAS**

### 2.2 签名与换机（重要）

APK 用的是 **2024-01-17 生成的 debug keystore**，一直沿用，别再生成新的：

| 项目 | 值 |
|---|---|
| keystore（项目外） | `~/keys/piggy-pal-debug.keystore`（权限 600） |
| 配置 | `client/android/key.properties`（不进 git） |
| alias | `androiddebugkey` |
| 密码 | `android` |
| SHA-256 指纹 | `A8:EC:22:C1:D2:55:C0:AE:54:36:BB:B4:10:53:03:8E:E6:74:30:95:F1:63:A6:53:53:AC:A0:07:F8:3B:B5:6E` |
| 有效期 | 2054-01-09 |

**为什么不能换**：Android 只允许同签名的包覆盖安装。换了签名 → 已装设备报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`，只能卸载重装；而且 `ANDROID_ID` 按签名派生，`client_id` 会变，日志和设备记录会断档。

发版脚本 `release_apk.sh` 每次都会校验指纹，不一致直接中止，不会传到线上：

```bash
$APKSIGNER verify --print-certs client/build/app/outputs/flutter-apk/app-release.apk
```

**换电脑 / 重装系统**：

```bash
# 1. 从密码管理器或离线备份取回 keystore
mkdir -p ~/keys && chmod 700 ~/keys
cp <备份>/piggy-pal-debug.keystore ~/keys/piggy-pal-debug.keystore
chmod 600 ~/keys/piggy-pal-debug.keystore

# 2. 新建 client/android/key.properties（内容见上表，storeFile 用绝对路径）
# 3. 打包前确认指纹
keytool -list -v -keystore ~/keys/piggy-pal-debug.keystore -storepass android \
  | grep SHA256
```

**备份 checklist**（三处，缺一不可）：

1. 密码管理器：keystore 文件 + 密码 + 指纹
2. 离线介质（U 盘 / NAS）：同一份文件
3. 纸质记录：alias、SHA-256 指纹、生成日期（不写密码）

**已有异地副本**（2026-10-26 放置）：

```
腾讯云 203.0.113.10 : /root/backups/keys/piggy-pal-debug.keystore   600 root
                        /root/backups/keys/README.txt（恢复步骤 / 指纹 / 文件 sha256）
```

- 在 `/root` 下（`700`），`piggy-pal` 服务用户读不到，也不在 Web 目录里，不会被 `deploy.sh` 覆盖
- 取回：`scp root@203.0.113.10:/root/backups/keys/piggy-pal-debug.keystore ~/keys/`
- 校验：`shasum -a 256` 应为 `4a483e7274a81773e9e0cf5fd715869f62409b04f1eee57f5ebd46be817a29eb`
- 注意：这是**同机同盘**的副本，服务器磁盘挂了就一起没；它挡的是「本机丢失」，挡不住机房故障，所以密码管理器 + 离线介质仍必须做

> 丢了这把 key 就永远无法给已安装的 App 发更新，只能逐个卸载重装，这是不可逆的。keystore 绝不进 git（`.gitignore` 已覆盖 `key.properties` / `*.jks` / `*.keystore`）。

另外：漏了 `key.properties` 时 **release 构建会直接失败**并提示恢复路径；`flutter run`（debug）不受影响。

## 3. 分流判断

| 现象 | 客户端日志 | 服务端日志 | 结论 |
|---|---|---|---|
| 页面一直转圈 | 有 `api: →` 无 `←`，或 `[W]` 读缓存失败 | 没有请求 | 客户端问题 |
| 页面报错 / 空数据 | `← 401/500` | 有请求 | 服务端或鉴权 |
| 请求都没发 | 无 `api: →`，无 `[W]` | 无 | 页面逻辑卡住（loading 没结束） |
| 闪退 | `[E] app: 未处理的...异常` | 无关 | 看堆栈定位代码 |
| 语音没反应 | `[W] chat: 录音启动失败` | 无 `chat` 请求 | 麦克风权限 / 录音插件 |

## 4. ADB 兜底（最后才用）

只在前面的日志都拿不到（App 起不来、日志目录不可用、需要看原生崩溃）时使用。**每条命令都加 `timeout`**：

```bash
export PATH=~/Library/Android/sdk/platform-tools:$PATH

# 原生崩溃 / Flutter 引擎异常（10 秒内取完，不要 -f）
timeout 10 adb -s d1193609 logcat -d | grep -E "FATAL|AndroidRuntime|E flutter" | tail -40

# 当前前台页面（判断是不是停在启动页 / 系统弹窗）
timeout 10 adb -s d1193609 shell dumpsys window | grep mCurrentFocus

# 截图确认界面状态
timeout 20 adb -s d1193609 exec-out screencap -p > /tmp/shot.png
```

注意：

- 不要用 `adb logcat -f`、`adb devices -l` 这类可能长时间阻塞的命令
- 多设备时**必须带 `-s <序列号>`**，否则会报 `more than one device`
- 模拟器 DNS 不可用，只能验证本地逻辑，不要用它判断线上网络问题

## 5. 已踩过的坑（案例库）

### 2026-10-25 选宝宝页 / 星星页一直 loading

- **表象**：release 包进选宝宝页、星星页无限转圈，服务端日志只有 `/roles`，没有 `/child`、`/stats`
- **客户端日志**：`[W] home: 读取宝宝缓存失败: PlatformException(... NoSuchMethodError ...Continuation ...)`，随后 `[W] child: 加载宝宝列表失败`
- **根因**：Flutter release 默认开启 R8，`shared_preferences_android` 通过 JNI 按名字调用 Kotlin suspend 方法，`kotlin.coroutines.Continuation` / `CoroutineSingletons` 被改名或裁掉
- **修复**：`client/android/app/proguard-rules.pro` keep 插件与 JNI 运行时类
- **防回归**：`./build.sh` 打完包用 `dexdump` 校验签名；CI 每次 push 打 release 包跑同一套校验
- **教训**：debug 正常 ≠ release 正常；页面转圈先看「服务端有没有收到请求」
