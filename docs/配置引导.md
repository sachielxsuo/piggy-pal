# 配置引导（新机器 / 新开发者）

> 从 `git clone` 到「能跑、能部署、能发版」，需要哪些文件、每个字段填什么。
> **仓库里只有 `*.example` 模板，真实值一律不进 git**，这是硬约定，见 `AGENTS.md`。

## 0. 一分钟速查

| 你要做什么 | 需要准备 |
|---|---|
| 只改后端、在电脑上跑 | `server/.env` |
| 手机真机调试 | `server/.env` + `deploy.env` |
| 部署到自己的服务器 | 上面这些 + 服务器 SSH + 服务器上已有 `config/` 和 `.env` |
| 发 Android 包 | 上面这些 + `client/android/key.properties` + keystore 文件 |

## 1. 环境

| 工具 | 版本 | 用途 |
|---|---|---|
| Go | `>= 1.22`（见 `server/go.mod`） | 后端 |
| Flutter | 能提供 Dart `^3.13.5`（见 `client/pubspec.yaml`） | 客户端 |
| Android SDK | 带 `build-tools`（`dexdump`/`apksigner`） | 打 APK、校验签名 |
| rsync | 任意 | `release_apk.sh` 在中性目录打包，`backup-secrets.sh` 无依赖 |
| Xcode | 可选 | 只在打 iOS 时需要 |
| whistle | 可选 | 真机调试代理 |

Flutter 不在 `PATH` 里也没关系，`release_apk.sh` 会依次找 `PIGGYPAL_FLUTTER_BIN` → `$FLUTTER_ROOT/bin` → `~/flutter/bin` → Homebrew。

## 2. 配置文件总览

| 文件 | 模板 | 是否必须 | 谁读它 | 进 git |
|---|---|---|---|---|
| `server/.env` | `server/.env.example` | 跑后端就要 | Go 服务（`systemd` 也是从这里读） | ❌ |
| `deploy.env` | `deploy.env.example` | 部署 / 发版就要 | `deploy.sh` / `build.sh` / `run.sh` / `release_apk.sh` | ❌ |
| `client/android/key.properties` | 手写（见第 5 节） | 发 Android 包就要 | Gradle 签名配置 | ❌ |
| keystore（`.keystore`） | 自己生成或恢复 | 同上 | 同上 | ❌ |
| `/opt/piggy-pal/alert.env` | `deploy.sh` 自动生成 | 想要告警才要 | 巡检脚本 `piggy-pal-watchdog` | ❌（在服务器上） |
| `client/android/local.properties` | Flutter 自动生成 | 不要手写、不要提交 | Gradle | ❌ |
| `client/assets/<role_id>.png` | 自备（见第 6 节） | 想要角色图才要 | Flutter 资源打包 | ❌ |

> 前四个文件加起来不到 4KB，全部属于「密钥」，备份和恢复见 [密钥与恢复.md](密钥与恢复.md)。

## 3. `server/.env`

```sh
cd server
cp .env.example .env
chmod 600 .env
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `TENCENTCLOUD_SECRET_ID` / `SECRET_KEY` | 调试必填 | 腾讯云 CAM 密钥，控制台 → 访问管理 → API 密钥管理。**子账号**只给 TTS/ASR 权限即可 |
| `TENCENTCLOUD_REGION` | 否 | 默认 `ap-guangzhou` |
| `LLM_TOKEN` | 必填 | DeepSeek API Key（`sk-` 开头），platform.deepseek.com |
| `LLM_BASE_URL` / `LLM_MODEL` | 否 | 默认 `https://api.deepseek.com` / `deepseek-chat` |
| `ASR_ENGINE` | 否 | 默认 `16k_zh-PY`（中英粤混说）；纯英文可用 `16k_en` |
| `API_TOKEN` | **公网部署必填** | 全站共享令牌，`openssl rand -hex 24` 生成。留空 = 关闭校验，只适合本地 |
| `PORT` | 否 | 默认 `18080` |
| `DATA_DIR` | 否 | 默认 `./data`（SQLite + TTS 缓存） |

⚠️ **`API_TOKEN` 会被编译进 APK**。改了它，所有设备都必须重新打包升级，否则一律 401。轮换前先想清楚。

## 4. `deploy.env`

```sh
cp deploy.env.example deploy.env
chmod 600 deploy.env
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `PIGGYPAL_SERVER` | ✅ | 服务器公网 IP 或域名（`ssh` 的目标） |
| `PIGGYPAL_USER` | 否 | 默认 `root` |
| `PIGGYPAL_DOMAIN` | ✅ | 对外域名。**客户端的 API 地址也从这里来**（`https://$PIGGYPAL_DOMAIN`） |
| `PIGGYPAL_REMOTE_DIR` | 否 | 默认 `/opt/piggy-pal` |
| `PIGGYPAL_API_BASE` | 否 | 想单独指定 API 地址时用（比如先指向预发环境） |

- 命令行环境变量优先级更高：`PIGGYPAL_SERVER=1.2.3.4 ./deploy.sh`
- 缺 `PIGGYPAL_SERVER` / `PIGGYPAL_DOMAIN` 时脚本**直接报错退出**，不会静默连错地方
- 客户端不写死域名：`build.sh` 会注入 `--dart-define=API_BASE_URL=https://$PIGGYPAL_DOMAIN`
- 仓库里所有文档的 `203.0.113.10` / `piggy.example.com` 都是占位符，替换成你自己的值

## 5. 客户端签名

Android 必须有签名才能装。**签名一变，已安装的设备只能卸载重装**（数据全丢）。

`client/android/key.properties`：

```properties
storeFile=/absolute/path/to/your.keystore
storePassword=你的密码
keyAlias=你的别名
keyPassword=你的密码
```

- `storeFile` 建议用绝对路径，放在项目外（比如 `~/keys/`）
- 没有 keystore 就自己生成一个（新项目可以，**已有设备在用的项目不能换**）：

```sh
keytool -genkeypair -v -keystore ~/keys/piggy-pal.keystore \
  -alias piggypal -keyalg RSA -keysize 2048 -validity 36500
```

- `release_apk.sh` 发版前会校验 SHA-256 指纹，对不上直接中止：

```sh
keytool -list -v -keystore ~/keys/piggy-pal.keystore -storepass <密码> | grep SHA256
```

- 只想本地跑、不发版，可以完全不管这一节（`flutter run` 用调试签名）

## 6. 角色形象（本地自备，不进仓库）

`client/assets/peppa.png`、`george.png` 这类角色图**版权归各自权利人**（小猪佩奇等），
所以不在仓库里，`.gitignore` 已经把它们排除了。缺了不影响编译和运行：

- 客户端从服务端拿到 `role_id`，按约定读 `assets/<role_id>.png`
- 读不到就退化成「角色名首字 + 纯色圆」，见 `client/lib/widgets/role_avatar.dart`

想要真图就自己放一份：

```sh
cp 你的图/peppa.png  client/assets/peppa.png
cp 你的图/george.png client/assets/george.png
```

文件名必须和服务端 `server/config/roles.yaml` 里的 `role_id` 一致（`peppa` → `peppa.png`）。
新增角色同理，丢一个 `<role_id>.png` 进去就能用。

⚠️ 这两张图会被打进 APK。自己用没问题；要公开发布客户端，记得换成有授权的形象。

App 图标和启动图是**原创图形**（脚本画的通用小猪脸），随仓库以 MIT 授权，
不含任何第三方角色形象。改了配色想重出一套：

```sh
python3 scripts/gen_app_icons.py            # 覆盖 Android / iOS 全部尺寸
python3 scripts/gen_app_icons.py --preview  # 只看一张 1024 预览
```

## 7. 三种场景

### A. 只在本地跑后端

```sh
cp server/.env.example server/.env   # 填 CAM 密钥 + LLM_TOKEN
./server.sh                          # :18080
curl -s localhost:18080/healthz      # {"status":"ok"}
```

`API_TOKEN` 留空最省事（关闭校验）。想验证校验逻辑再随便填一个。

### B. 手机真机调试（走 whistle）

```sh
cp deploy.env.example deploy.env     # 填 PIGGYPAL_DOMAIN
./run.sh                             # 自动抓局域网 IP 并注入 whistle 代理
```

whistle 规则（值取自 `deploy.env` 的 `PIGGYPAL_DOMAIN`）：

```
你的域名 http://127.0.0.1:18080
```

`run.sh` 会把 `WHISTLE_PROXY`、`API_TOKEN`、`API_BASE_URL` 一起 `--dart-define` 进去，不需要手改代码。

### C. 部署服务端

```sh
cp deploy.env.example deploy.env     # 服务器 IP + 域名
cd server && cp .env.example .env    # 填生产密钥

./deploy/deploy.sh --with-env        # 首次：顺便把本地 .env 传上去
./deploy/deploy.sh                   # 之后：只换二进制和配置
```

脚本会自己：交叉编译（`-trimpath`）→ 在线备份数据库 → 标维护 → 排空停服 → 换版本 → `/readyz` 校验 → 失败自动回滚。

前提：服务器上有 Go 以外的运行时不需要，但要能 `ssh`、要有 `sudo`、80/443 放行、域名 A 记录指向它。

### D. 发客户端

```sh
# 1. 版本号加一（+ 后面是 versionCode，必须递增）
#    client/pubspec.yaml: 1.0.19+20 -> 1.0.20+21
# 2. 打包 + 上传 + 写 latest.json
./release_apk.sh "更新说明"
```

- 默认在一个**中性临时目录**里打包，避免 APK 里带开发机路径（`PIGGYPAL_BUILD_IN_PLACE=1` 可跳过）
- 发版前会校验签名指纹和 `versionCode`
- `--min N` 能让低于 `N` 的客户端强制更新；`--force` 等价 `--min 本次 versionCode`

## 8. 常见错误对照

| 现象 | 原因 |
|---|---|
| `❌ 缺少部署配置：PIGGYPAL_SERVER / PIGGYPAL_DOMAIN` | 没建 `deploy.env`，或字段空着 |
| `❌ 没有 API 地址：客户端会连不上后端` | `build.sh` 读不到 `deploy.env` |
| 接口全 401 | 客户端 `API_TOKEN` 和服务端不一致（改过 token 但没重打包） |
| 真机连不上、电脑能连 | `deploy.env` 的域名没配 whistle 规则；或手机和电脑不在同一 Wi-Fi |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | 签名变了，只能用原 keystore 重打，或卸载重装 |
| `❌ 签名指纹不一致` | `key.properties` 指向了另一个 keystore |
| `找不到 flutter 命令` | 设 `PIGGYPAL_FLUTTER_BIN=/path/to/flutter` |

## 9. 提交前自查

```sh
git status                     # 确认 .env / deploy.env / key.properties 没被 add
git grep -nE "/Users/|([0-9]{1,3}\.){3}[0-9]{1,3}|@[a-z0-9.-]+\.(com|cn)"
```

应为空，或只剩文档里的占位符（`203.0.113.10` / `piggy.example.com`）。
